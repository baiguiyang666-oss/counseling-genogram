## 一、硬约束（不可协商）

1. **单文件交付**：最终产物是一个 `index.html`，HTML、CSS、JavaScript 全部内联，不拆分、不构建、不产出额外资源文件。
2. **零外部依赖**：不得引用任何 CDN、外链字体、外链图片、外链样式、第三方脚本或网络接口（包括图标库）。所有图形由内联 SVG 或 Canvas 绘制，所有字体只用系统字体栈（如 `-apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", "Noto Sans SC", sans-serif`）。
3. **完全离线**：断网状态下所有功能（编辑、排版、导出、存档）必须可用。
4. **双击即开**：通过 `file://` 直接打开就能完整运行，不依赖本地服务器，不使用 ES Module 的跨文件 import，不使用 Service Worker。
5. **商用成熟度**：有撤销/重做、自动保存、错误提示、空状态、键盘可达、屏幕阅读器标签；控制台无报错；不出现 `undefined` / `NaN` 字样；不丢数据。
6. **隐私**：数据只写入本机浏览器本地存储，不上传、不埋点、不请求任何远端。
7. **实现语言**：原生 HTML/CSS/JavaScript，不引入框架。代码总量以能完整实现本规格为准。
8. **署名与许可：界面零署名，但必须写明商用署名要求（严格）**：作者署名与许可声明**只出现在源码注释块中**（例如文件最顶部 `<!-- ... -->` 里写明许可证、版权行，并用一句话写清"个人使用不在界面显示署名，商用必须按 `NOTICE` 要求在显著位置署名"）。**不得出现在任何外部可见视图**，包括但不限于：工具栏与按钮、状态栏、页脚、关于/信息弹窗、提示条、空状态、符号图例、导出预览、导出 PNG 的画面角落、导出 PDF 的页眉页脚与第 2 页明细、打印页、导出 HTML 的 `<title>` 与正文。禁用字样：作者名、项目署名、`MIT`、`License`、`Copyright`、`©`，以及 `Generated by …` / `Powered by …` 之类的变体。
   - 理由：署名与授权必须随代码一起流转，但它是源码层信息，不应污染使用者看到的界面，更不应出现在交付给来访者或督导的文档上；同时商用边界必须写清楚，否则"零署名"会被误读成"无需署名"。
   - 推论：不设「关于」对话框来放版权；需要展示版本信息时，只显示版本号与构建日期，不显示作者与许可证。
   - 配套：源码注释里**必须**同时写明两点——① 个人使用：界面与导出物不显示署名，也无需署名；② 商业使用：必须署名。并在 `LICENSE` / `NOTICE` 中给出可执行的商用署名方式（保留版权声明与许可全文、在显著位置署名并附仓库链接）。

## 二、产品定位与使用场景

这是一款给心理咨询师、家庭治疗师、社工与医学工作者使用的**家谱图绘制与记录工具**。

典型场景：
- 首次访谈时，边谈边把家庭成员、伴侣关系、亲子关系、情感关系画出来；
- 用符号表达已故、离异、分居、收养、流产、未出生、冲突、断绝、虐待等临床信息；
- 为同一位来访者绘制跨三代的结构图，并标注职业、诊断、重要经历、原话与标签；
- 会谈结束后，把图导出为图片或 PDF 存入个案记录；
- 下一次会谈打开工具，全部内容与视图位置原样恢复。

使用者的核心诉求是：**画得快、改得动、符号准、排版不乱、导出能直接用**。因此：
- 一切高频操作（新增人物、拉关系、改关系类型、改符号、加条目）都要在 1–2 步内完成；
- 布局必须自动，且不能因为一次刷新把用户摆好的位置全部打散；
- 符号含义必须可查，不能要求使用者背符号表。

## 三、界面骨架

1. 顶部一条工具栏，高度约 44px；右侧固定属性面板，宽 340px；其余区域为画布。
2. 画布为浅色点阵背景，点距 26px，可平移、可缩放。画布左上角的世界坐标留白 60px。
3. 属性面板按选中对象切换：未选中时显示全局设置（标题、主题、导出）；选中人物时显示人物详情；选中伴侣单元时显示伴侣详情；选中情感线时显示情感详情。
4. **界面上不得出现任何操作提示文案**：不写“拖动可移动”“双击可编辑”“按 Esc 取消”这类引导句，不放常驻快捷键说明，不在画布上叠加操作提示气泡。允许的文本只有：字段标签、按钮文字、空状态的一句状态说明、瞬时操作反馈（如“已导出”“日期格式不正确”）与错误提示。
5. 所有可点击元素都要有可见焦点状态（焦点框 1.8px），并带 `aria-label`；符号要输出可读的无障碍描述（姓名、性别、出生、已故、未出生等）。
6. 选中态：人物符号外加 34px 半宽的选择框（描边 1.8px），连线加 6px、透明度 0.14 的同色光晕。
7. 界面不留品牌位：没有页脚品牌条、没有角落水印、没有版权行；署名与许可只存在源码注释里，界面不显示，但注释中须写明"个人使用零署名、商用必须署名"（见第一章第 8 条）。

## 四、符号体系（本工具的灵魂）

### 4.1 单一数据源（强制架构要求）

必须建立一张**符号注册表**，每个符号是一条记录，至少包含：

| 字段 | 含义 |
|---|---|
| `code` | 稳定标识，如 `person_female`、`cpl_divorce`、`kid_adopted`、`emo_conflict` |
| `name` | 中文名称，如「女性」「离婚」「收养」「冲突」 |
| `draw` | 图形画法描述（形状、线型、虚线节奏、线宽、颜色、线中标记、箭头） |
| `meaning` | 临床语义一句话 |
| `group` | 归属：人物 / 伴侣 / 亲子 / 情感 |
| `ext` | 是否为非标准扩展画法（图例要打「扩展」角标） |
| `defaultDirection` | 情感线是否默认带方向（施害者 → 受害者） |

**渲染、图例、含义说明、选择器这四处必须全部由这张表驱动**，不得各自硬编码。验收方式：临时在表里新增一条符号，刷新后画布可画、图例出现、含义说明出现、下拉可选，四处同时生效，且不需要改第二个地方。

### 4.2 人物符号

统一外接框 56×56（半径 R=28），描边 1.6px，填充为浅色/白色。图形以符号中心为原点。

| 代码 | 名称 | 画法 | 语义 |
|---|---|---|---|
| `person_male` | 男性 | 正方形 56×56 | 最基础的男性符号 |
| `person_female` | 女性 | 圆形 r=28 | 最基础的女性符号 |
| `person_unknown` | 性别未明 | 菱形，四点为 (0,-28)(28,0)(0,28)(-28,0) | 性别未知；三角形专留给怀孕，不得挪用 |
| `person_nonbinary` | 非二元 | 下半矩形 + 上半圆：`M-28 28 V0 A28 28 0 0 1 28 0 V28 Z` | 非二元性别 |
| `person_intersex` | 间性 | 圆 r=28 + 圆内竖线 x=0，端点距上下边 2px | 间性 |
| `person_trans_male` | 跨性别男 | 外方 56×56 + 内圆 r=14 | 外方内圆 |
| `person_trans_female` | 跨性别女 | 外圆 r=28 + 内方 28×28 | 外圆内方 |
| `person_pet` | 宠物 | 菱形 + 虚线 4 3 | 宠物，主体地位弱于家庭成员 |
| `person_index` | 索引咨访 | 在基础形状外再套一层轮廓，外扩 3px（半径 31）；方、圆、菱形必须同形，拱形/间性/跨性别等复合形状用 62×62 外框 | 索引咨访（Proband），全图唯一，是聚焦对象 |
| `person_deceased` | 已故 | 符号内部打叉；圆形按内接 45° 裁到 r≈19.8，方形到 ±27.2，拱形/宠物到 ±20.2 | 已故；叉线不得越出符号边界 |
| `person_age` | 年龄 | 符号中心显示数字，字号 13px / 字重 500 | 健在显示当前年龄，已故显示寿年；无出生日期显示 `?` |

附加规则：
- 索引咨访的双框：方形/圆形/菱形与基础形状同形，只外扩 3px；拱形、间性、跨性别等复合形状用 62×62 的方形外框，避免内外形状互相干扰。
- 已故叉线用 1.4px、透明度 0.55 的线条；若中心同时显示年龄数字，数字必须带 3px 背景色描边（halo）保证可读。
- 怀孕：在符号右下角内切位置画三角形，底边约 16.8px、高约 15.7px，中心约在 (14.6, 14.6)，不得与年龄数字重叠。
- 流产：同一位置画实心小圆点，半径约 4.8px。
- 未出生：不显示年龄数字（避免把孕周误读为年龄），可有明显弱化的轮廓；孕周只在属性面板显示。
- 出生日期显示在符号左上方（右对齐到 x=-39、y=-37），死亡日期显示在右上方（x=36、y=-37），都只显示到「年-月」，字号 11px。
- 姓名显示在符号下方，首行基线 y=43，字号 13px / 字重 500，居中；最多两行姓名，行距 15px，超过 168px 自动折行。
- 节点内信息条目从姓名最后一行下方 14.7px 开始，条目字号 12px，行距 13.5px；条目超过 4 行时行距放宽到 14.4px。
- 节点内最多显示 6 条实际条目，第 7 行固定为 `+N` 汇总行；超出时显示 `+N` 圆形角标（半径 11px）在符号右上角。

### 4.3 伴侣关系（`union` 是一等实体）

伴侣线画在两位人物符号的**中心高度**上，从 A 的右侧端口连到 B 的左侧端口，线宽按下列表；关系标记画在整条线**中点**。

| 代码 | 名称 | 画法 | 语义 |
|---|---|---|---|
| `married` | 结婚 | 实线 2px | 标准婚姻/伴侣关系 |
| `engaged` | 订婚 | 点线 `2 4`，1.5px | 已订婚未成婚 |
| `cohabiting` | 同居 | 虚线 `5 3`，2px | 未登记但共同生活 |
| `dating` | 交往 | 细虚线 `3 3`，1px | 关系尚未固定 |
| `affair` | 婚外情 | 红色 `#b23a34` 虚线 `4 4`，1.5px | 婚姻之外的隐秘关系 |
| `oneNight` | 一夜情 | 稀疏点线 `2 6`，1.5px | 单次性关系 |
| `separated` | 分居 | 实线 2px + 1 条斜杠 | 分居，婚姻未解除 |
| `divorced` | 离婚 | 实线 2px + 2 条斜杠 | 法律离婚，斜杠在中段 |
| `broken` | 断绝 | 实线 2px + 空心圆加斜杠（⊘） | 关系断绝、互不往来 |
| `remarried` | 再婚 | 实线 2px + 两个空心小方框 | 再婚 |
| `widowed` | 丧偶 | 实线 2px + 线中 × | 配偶一方已故 |
| `annulment` | 婚姻无效 | 2 斜杠 + × | 婚姻被宣告无效/撤销 |
| `rape` | 强迫/性侵关系 | 红色粗实线 3px + 粗 × | 非自愿性关系，标注需极度审慎 |
| `consanguineous` | 血亲婚配 | 双平行实线，偏移 ±1.5px | 近亲婚姻 |
| `custodyLeft` | 离婚·A 方监护 | 2 斜杠，整体偏向 A 侧 22% | 离婚后监护权归 A 方 |
| `custodyRight` | 离婚·B 方监护 | 2 斜杠，整体偏向 B 侧 22% | 离婚后监护权归 B 方 |

规则：
- 一个人可以有多段伴侣关系。同一人的多段关系按 `order` 排列，伴侣在同行中左右交替布置（甲—乙—甲—丙），不得把同一人的两段关系叠在一条线上。
- 只有一方时（单亲），不画伴侣线，直接从中继线向下接子女。
- 伴侣关系可带开始/结束日期，显示在中继点上方：开始日期在关系线上方约 35px、结束日期在下方约 15px；若该伴侣有子女、中继线占用了中点，则两个日期分别上移到 -10、下移到 +19 的位置，避免压线。
- 「离婚·A/B 方监护」不是独立关系类型，而是离婚的监护权变体，选择器里必须能直接选到。

### 4.4 亲子关系

亲子走线：伴侣线中点 → 中继竖线 → 兄弟姐妹横条 → 各子女竖线（详见第六节）。亲子类型只改变**子女竖线**的线型，可与实线组合。

| 代码 | 名称 | 画法 | 语义 |
|---|---|---|---|
| `biological` | 亲生 | 实线 1.5px | 血缘亲子 |
| `adopted` | 收养 | 长虚线 `8 4` | 法律收养 |
| `foster` | 寄养 | 密点线 `2 3` | 非法律亲子 |
| `step` | 继子女 | 点划线 `8 3 2 3` | 继子女 |
| `guardian` | 监护 | 点线 `2 3` + 字母 `G` | 非父母承担监护 |
| `surrogate` | 代孕 | 虚线 `5 3` + 字母 `S` | 代孕所生子女 |
| `spermDonor` | 精子捐赠 | 点线 `2 4` + 字母 `SD` | 捐精所生子女 |
| `eggDonor` | 卵子捐赠 | 虚线 `8 4` + 字母 `ED` | 捐卵所生子女 |

规则：
- 除「亲生」外，其余亲子类型在图例中打「扩展」角标。
- 同一子女可以同时拥有多个亲子链接（例如收养 + 亲生），但**只有一个**是主链接（`primary=true`），只有主链接参与中继/兄弟条布局；其余为附加链接，用一条额外的短竖线或斜线接到该子女符号的侧边，不得重复画兄弟条。
- 兄弟组只统计主链接，避免一个人被画进两个兄弟条。

### 4.5 情感关系

| `note` | string | 关系备注 |

| 字段 | 类型 | 说明 |
|---|---|---|
| `union` | unionId | 属于哪个伴侣单元 |

|---|---|---|
| `id` | string | 唯一 |

### 5.5 日期与状态的一致性约束（强制）

- 日期只允许四种取值：`YYYY`、`YYYY-MM`、`YYYY-MM-DD`、空。用 `-` 作为分隔符；用户输入 `/` 或 `.` 时自动归一化。
- 年份范围 1850 到当前年；月份 1–12；日期必须是该月真实存在的日期（2 月 30 日非法）。
- **未出生 ⇒ 出生日期必须为空**。取消未出生时，把备份值原样回填。任何路径（属性面板、导入、自动修复）都不得产出「未出生且有出生日期」的状态。
- **死亡日期非空 ⇒ 已故必须为真**。填写死亡日期自动置为已故；取消已故必须同时清空死亡日期，不允许出现「未已故但有死亡日期」。
- 未出生时隐藏死亡日期、已故、怀孕/流产字段；怀孕与未出生是不同概念，不得互斥到丢失数据。
- 索引咨访全图唯一；已存在时再选他人必须拒绝并提示先取消，不得静默转移。
- `union` 的 `a`、`b` 不得相同；不得让同一个人在同一段关系中重复出现。
- 亲子链接的 `union` 必须存在，`child` 不得是该 union 的 a/b 本人（禁止自环）。
- 所有外键在载入时必须校验，指向不存在对象的链接要丢弃并记录警告，不能让界面崩掉。

### 5.6 信息条目 `note`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 唯一 |
| `type` | string | 类别 id |
| `value` | string | 内容，纯文本，允许换行 |
| `label` | string | 自定义类别名（可选） |

类别来源：每个人物自带 `cats`，默认 5 类——职业、诊断、经历、原话、备注；「标签」不进入类别下拉，由顶部 chips 输入承担。类别 id 与名称一一对应，删除类别时其下条目要转入其他类别，不得丢失。

## 六、自动排版与布线（最关键的部分）

所有数值单位是画布世界坐标 px。

### 6.1 分代成行

1. 初始把所有人放在第 0 代。
2. 伴侣同代：没有父母链接的一方被上提到另一方所在代，避免「伴侣跨代」。
3. 反复传播：子女代 = 其伴侣单元所在代 + 1；最多迭代 `min(60, 人数+4)` 轮。
4. 最后把最小代归零，防止异常数据留下整片空白行。
5. **同一代的所有人物，符号中心 y 必须完全相同**（同代 y 极差 = 0）。行基准 y 只由代决定，个人纵向偏移单独叠加。

### 6.2 行距

- 每代的基准 y 从 0 开始；下一代 y = 本代 y + 本代最高节点高度 + **96px**。
- 节点高度包含符号、姓名、信息条目：单行姓名时约 77px，因此单行姓名相邻两代的中心距约 **173px**；两行姓名约 **188px**。
- 不得用固定行距把高节点压到下一代文字上；行距只由本代实际节点高度决定，不得额外叠加「避让余量」，条目多的人物自然撑高本代。

### 6.3 代内顺序

1. 以「代内第一个未被放置的人」为种子。
2. 深度优先：先按每段伴侣的 `order` 把伴侣插入到当前人的左右两侧（左右交替，甲—乙—甲—丙）。
3. 再按子女顺序展开：先按 `parentLink.order`，其次按年龄从大到小（年长者在左），最后按 id 稳定排序。
4. 无任何关系的人物追加到**最上代（第 0 行）的最左侧**，不得凭空虚增一代。
5. 排序必须稳定：同一份数据两次计算，顺序完全一致。

### 6.4 伴侣相邻

- 一对伴侣在同行中必须紧邻，中间不得插入第三人。
- 一对伴侣的最小中心距 **140px**（净距 84px = 1.5 个符号框宽），这是「有连线直接相连」的档位。
- 同一人的多段伴侣，左右交替排列；不得把两段关系画在同一段线上。

### 6.5 中继线与子女

1. 伴侣单元中点 `ux = (xA + xB)/2`；单亲时 `ux = xA`。
2. **单子女**：中继竖线的 x 必须精确等于 `ux`，子女符号中心 x 也必须被拉到 `ux`；这条竖线必须是**一条竖直直线**，从伴侣线中点直落到子女符号上沿（`y - 28`）。中点偏差 **≤0.5px**，求解器内部按 **0.01px** 容差做刚性回贴，并在邻居让位后再复算一次中点，验收时实测应为 **0.00px**。
3. **多子女**：
   - 先按最小间距把该组子女依次排开，得到相对位置；
   - 取首尾中心的中点，把整组平移，使**首尾两端中心的中线 = `ux`**，偏差 **≤0.2px**；
   - 当全组子女都只有这一个主链接、且两位父母都存在时，执行**等间距**：相邻中心距统一为 `g = max(该组每对的最小中心距, 126, (最高x-最低x)/(n-1))`，整组仍以 `ux` 为轴，等间距误差 **≤0.5px**（实测应为 0.00px）；
   - 兄弟姐妹横条覆盖从最左子女中心到最右子女中心（含中继线 x），不得短于两端。
4. **T 型接头闭合**：子女竖线的上端必须精确落在兄弟横条的 y 上（偏差 **≤0.6px**），横条要覆盖每条竖线的 x，不得出现 1px 断口或横条出头一大截。
5. 中继线 lanes：若两条中继线的 x 相距小于 **14px**，后一条的兄弟横条整体上移 **9px**，最多堆叠 3 条；上移后仍需满足 T 接头闭合。
6. 兄弟横条的 y：至少比伴侣线低 18px，且至少比子女符号上沿高 14px；不得压到任何名字或条目。

### 6.6 间距底线（硬约束）

| 场景 | 最小中心距 | 最小净距 | 说明 |
|---|---|---|---|
| 任意相邻两框 | 126px | **70px**（≈1.25 框宽） | 全局硬底线，任何关系都要满足 |
| 有连线直接相连（伴侣、情感线） | **140px** | **84px**（=1.5 框宽） | 连接线必须看得清，不能贴框 |
| 文字盒之间 | (wa+wb)/2 + 28px | **28px** | 名字/条目不得相碰 |
| 情感线端口槽位 | 端口中心外偏 18px | — | 需要绕开日期文字时依次改用 26 / 34 / 44px |

规则：
- 净距低于底线必须拉开，且拉开是**成对**的（左右各让一半，或按冲突权重分配），不能只推一边导致另一边又压住别人。
- 若某对间距被约束撑开到远超底线（例如 > 3 倍），求解器必须尝试收紧；仍无法收紧的，必须能说明是被哪条约束撑开（独子中点、兄弟组居中、跨代避让、用户手动偏移）。说明信息要能在调试信息里查到，不能只存在于开发者脑子里。
- **用户手动偏移优先**：被用户拖过的人物（`|dragX| > 0.5`）不得被求解器拉回，只能围绕它推开别人。

### 6.7 收敛与幂等（强制）

- 求解流程：初始化 → 伴侣/子女目标 → 加权汇总 → 松弛 → 分离（迭代推开重叠）→ 兄弟组居中 → 等间距 → 独子纠偏；整套流程重复执行，直到**所有可见人物两轮之间的最大位移 < 0.02px** 或达到 **24 轮**上限。
- 分离迭代同样以 **0.02px** 为收敛阈值。
- 内层对齐循环以「本轮最大位移 < 0.6px」为停。
- 结果必须**幂等**：写回的 `offset` 为最终 x 减去「无偏移基准 x」。同一份数据刷新两次，所有人物坐标的差值必须为 **0.00px**（逐位相同，不是「差不多」）。
- 任何一次刷新都不得改变 `offset` 的语义；不得把计算结果再写回 `offset` 造成漂移。
- 运行时自检：每次渲染后断言中继竖线确实接到父母中点、子女竖线确实接到横条；不满足时在控制台报警，不得静默画出断线。

### 6.8 布线方向（只允许 90°）

- 结构线（伴侣、中继、兄弟条、子女竖线）只允许水平或垂直；任何斜线段数量必须为 **0**。
- 情感线同样必须是正交折线：候选路径为 1 折、2 折、3 折，端口只能取符号的上/下/左/右四边，端口外偏 **±18px** 作为槽位。
- 情感线代价函数（越小越优）：
  - 路径长度 × 0.02；
  - 穿过其他人符号框：+20000；
  - 穿过姓名/条目文字区：+12000；
  - 贴着符号边框共线跑：+8000；
  - 压住出生/死亡日期文字：+12000；
  - 压住伴侣状态标签（中继点上方以中继 x 为中心 ±32px（宽 64px）、纵向 y-55 到 y-1（高 54px）的区域）：+9000；
  - 与其他连线交叉：按交叉长度加权。
  - 端点符号只检查「向内穿入」，贴边出发不算穿入。
- 情感线的折返（先向左再向右）必须被判为非法候选；最终路径不得出现自交与折返。
- 选中连线时加 6px、0.14 透明度的光晕；线中标记不得因光晕而移位。

## 七、拖动行为

1. **点击与拖动必须区分**：指针按下后累计位移超过 **4px** 才算拖动；未超过则视为点击，打开属性面板、不进入拖动。拖动结束不得再弹出详情。
2. **横向 1:1 跟随**：世界坐标位移 = 屏幕位移 / 当前缩放。放大 2 倍时拖 100 屏幕像素，图上移动 50px，不得加速或减速。
3. **松手不回弹**：横向落点原样保留，不得自动回到原槽位、不得自动交换兄弟姐妹左右、不得自动重排伴侣。
4. **纵向分代带**：
   - 拖动过程中，核心人物只能在**本代带**内上下移动：符号盒上沿不得越过上一代人物线（至少留 34px），文字盒下沿不得越过下一代人物线（至少留 28px）。
   - 松手时，纵向精确对齐本代水平线（同代 y 极差为 0）；这就是「带内软吸附 + 硬边界」。
   - 当纵向位移 ≥ 行距的 **0.9 倍**时，视为越界，松手仍回本代线，不得跨代重排。
5. **非核心人物**（无任何伴侣单元、不是任何亲子链接的子女、也未被情感线连到核心图谱）豁免纵向钳制：可以自由落到任意 y，包括没有任何人的空带。
6. **拖到别人身上不得自动建立关系**：重叠只改变位置，求解器负责把两框推开；不得因为落点覆盖了某人就自动创建伴侣/亲子/情感关系。建立关系必须走显式入口。
7. 拖动时被拖人物置于最上层（z-index 提升），松手恢复层级。
8. 拖动不得破坏幂等：松手后写回 `offset`，再次刷新位置不变。

## 八、交互

### 8.1 选择与详情

- 点击人物：右侧面板切换到该人物；点击空白：回到全局面板。
- 点击伴侣线：显示伴侣单元详情（类型、开始/结束、备注、监护权变体、删除该关系）。
- 点击情感线：显示情感详情（类型、方向、反向、删除）。
- 选中后画布上必须有清晰选中态（34px 半框 + 连线光晕）。

### 8.2 新增人物

- 新建人物放到**最左侧**：取全体现有节点的最左外缘（`x - max(节点宽/2, 72)` 的最小值），新人物中心 x 落在该外缘再向左 **160px**，代次为第 0 行。
- 新建后必须**自动保证可见**：若新人物中心距画布可视边距小于 110px 或已在视区外，平移视图使其居中；缩放不变。
- 新建人物默认「性别未明」，姓名空显示「未命名人物」。
- 新建必须可撤销、可重做。

### 8.3 新增伴侣 / 新建情感线（两条入口，可取消）

必须同时提供：

1. **画布点选**：进入点选模式，顶部出现一条选择条，提示「请点选目标人物」和一个取消按钮（×）。点选任意其他人物即完成；点自己无效。
2. **下拉选择**：属性面板与右键菜单里提供「选择现有」的列表，列出除自己外的所有人物（按代、按姓名排序）。选择即完成。

取消规则：
- × 按钮、Esc、点击空白、再次点击同一入口，都算取消；
- **取消不得写入撤销栈**，不得产生任何数据变更，不得留下高亮残留；
- 取消后原选中对象保持不变。

其他规则：
- 新增伴侣默认类型「结婚」，默认放在同行右侧、中心距 140px；若对方已有其他伴侣，按 `order` 插入并左右交替。
- 新建情感线默认类型「正常/连接」，默认方向从当前选中人指向目标。

### 8.4 关系与符号的修改

- 改关系类型用下拉，改完立即重绘，不需要二次确认。
- 改人物符号时，性别大类与具体符号要联动但不能互相覆盖错误（例如把男性改成女性，符号必须跟着变；选「跨性别男」时性别大类为 other）。
- 删除人物必须二次确认，并说明将同时删除哪些关系；删除后不得留下悬空链接。

### 8.5 撤销 / 重做

- 撤销栈深度 60 步；重做栈对应。
- 文本输入连续修改以 800ms 为界合并为一步；下拉、勾选、拖动、删除、结构变更各为独立一步。
- 无变化的提交不得入栈（重复快照要去重）。
- 只读操作（选择、切换面板、展开图例、缩放、平移）不得入栈。

### 8.6 下拉的展开行为

- 任何枚举下拉展开时，若当前选中项不在可视区，必须**滚动到该项并高亮**。
- 由于浏览器原生 `select` 无法控制展开后的滚动与高亮，选项超过 8 项的枚举必须使用自绘列表框（可用键盘上下键、Enter 确认、Esc 关闭），不得依赖原生下拉。
- 自绘列表框必须能被外接键盘与遥控器操作，不得只能鼠标点。

### 8.7 其他

- 右键菜单提供：添加伴侣、添加子女、添加父母、添加情感线、设为索引咨访、折叠条目、删除。
- 首次打开且无本地存档时，加载一份可编辑的演示数据（至少三代、包含离异、再婚、已故、收养、两条情感线），让使用者立即看懂能力边界。
- 所有破坏性操作（删除人物、清空数据、删除类别）必须二次确认；清空数据要能先导出备份。

## 九、输入设备

同一套交互必须同时满足下列五类设备，且**界面上不得出现任何操作提示文案**，交互须符合常识。

### 9.1 鼠标

- 左键拖动平移画布；左键点选；滚轮缩放（每格 1.12 倍，以指针为锚点）；右键菜单。
- 双击人物进入姓名就地编辑（或聚焦面板姓名字段）。

### 9.2 键盘

- 方向键在人物之间移动焦点，按几何邻近选择（先找同方向、距离最近的框），焦点必须可见并自动滚入视区。
- Enter 打开/确认；Esc 取消点选、关闭弹层、退出编辑；Delete 删除选中对象（需二次确认）。
- `Ctrl/Cmd+Z` 撤销，`Ctrl/Cmd+Shift+Z` 或 `Ctrl/Cmd+Y` 重做。
- `+` / `-` 缩放 1.15 倍；`0` 适配全图。
- Tab 顺序必须覆盖工具栏、画布焦点、属性面板，不得陷在画布内出不来。

### 9.3 触屏

- 单指拖动平移；单指点击选择；单指拖动人物移动（同样遵守 4px 阈值）。
- **双指捏合缩放**：以两指中点为锚点，缩放范围 5%–400%；捏合过程中不得同时触发平移抖动；抬起一指后剩余一指继续平移。
- 触屏上不得出现 300ms 点击延迟；不得因 `touchstart` 与 `pointerdown` 双绑导致一次点击触发两次。
- 面板与弹层在窄屏下可占满宽度，但画布仍要能看到选中的人。

### 9.4 电视遥控器

- 方向键 / OK / 返回 键走同一套焦点系统；遥控器没有鼠标，所有操作必须能纯键盘完成。
- 焦点框要大、要明显；每次移动焦点都要自动滚入视区。
- 返回键等价 Esc；长按返回等价删除（需二次确认），不得与短按冲突。

### 9.5 游戏手柄

- 左摇杆 / 十字键移动焦点：死区 **0.25**，首次触发延迟 **400ms**，之后每 **150ms** 连发。
- A 键确认 / 打开；B 键返回 / 取消；长按 B **900ms** 等价删除（需确认）。
- 肩键（LB/RB）缩放：首次延迟 400ms，之后每 **220ms** 连发一档。
- 手柄与键盘同时接入时不得互相抢焦点；失焦后要释放所有按键状态。

## 十一、导出

三种格式都必须先给**所见即所得预览**，预览与最终文件使用同一份排版结果，不允许「预览小、导出大」或「预览有、导出缺」。

### 11.1 PNG

- 画布外框固定为 A4 横向比例：**1122×793px**，内容四周留白 **48px**。
- 支持 1 倍与 2 倍两档；2 倍时画布尺寸翻倍。
- 若计算出的任一边超过 **8192px**，自动把倍率减半，直到不超过 8192。
- 背景填充当前主题的画布色，不能透明；导出结果不得包含选中框、焦点框、点阵背景、工具栏、面板。
- 导出结果**不受当前缩放与平移影响**：始终按内容包围盒重新适配，而不是截取当前视口。
- 文件名安全化（去掉非法字符），并带倍率后缀。

### 11.2 PDF

- 通过打印通道生成，纸张 A4 横向，页边距 **10mm**。
- **必须两页**：第 1 页整页放图（等比适配），第 2 页是人物与关系文字明细。
- 第 2 页至少包含：
  - 每个人物：姓名、性别/符号、出生、死亡、年龄、未出生与孕周、已故、职业/诊断/经历/原话/备注、标签；
  - 每段伴侣：双方、类型、开始/结束、备注；
  - 每条亲子：父母单元、子女、类型；
  - 每条情感：双方、类型、方向。
- 分页不得把某个人物的明细拆到两页（`break-inside: avoid`）。
- 预览里要能翻到第 2 页查看文字明细，且预览内容与打印内容同源。

### 11.3 HTML

- 输出一个完全自包含的 HTML 文件：内联 SVG + 内联 CSS + 主题变量，无任何外链。
- 结构两节：第 1 节是图（带标题与日期），第 2 节是文字明细（同 11.2 的内容）。
- 打开导出的 HTML 不得依赖原工具，也不得残留编辑器控件。

### 11.4 其他

- 提供 JSON 备份导出与导入；导入必须走同一套校验与修复，不得让坏数据进入画布。
- 另提供「数据图例」导出（符号表 + 语义），供教学与督导使用。
- 导出过程要有进度/成功/失败提示；失败时给出可操作建议（例如「尝试导出 SVG」）。

### 11.5 导出产物的署名红线

- PNG、PDF、HTML、数据图例这四种产物都属于**对外交付物**，其可见内容中不得出现作者名、项目署名、`MIT`、`License`、`Copyright`、`©` 或 `Generated by` 类字样。
- 逐处点名：PDF 第 1 页页眉页脚、第 2 页明细的表头与表尾、每页的分页信息、打印页边距区域；导出 HTML 的 `<title>`、页首标题行、页尾；PNG 的图内角落与文件名。
- 导出 HTML 的**源码文本**同样不得携带许可注释：导出物是给来访者/督导的文档，不是本工具的源码副本，许可声明只保留在工具本体源码里。
- 零署名不等于放弃署名：工具本体的源码注释块里必须写明作者、许可证，以及"个人使用不署名、商用必须署名"这条要求；正文不得因为界面零署名就把署名义务一并删掉。
- 允许保留的元信息只有：文档标题（用户可编辑）、导出日期、页码。这三项都不含作者与许可证信息。

## 十二、主题与持久化

### 12.1 主题

- 内置 5 套主题：米白（默认）、冷灰、暖砂、青黛、藕荷。每套同时定义页面底色、画布色、面板色、正文色、次级文字色、分隔线、强调色、点阵色、符号填充色、连线色。
- 主题必须同时作用于：画布底色、符号填充、符号描边、符号内文字、连线、属性面板、弹层、导出图。不得出现「图变了、面板没变」的割裂。
- 允许自定义 3 个颜色：强调色、画布底色、符号填充色；自定义值要覆盖预设，且能一键恢复跟随主题。
- 主题选择立即生效，不需要刷新。

### 12.2 持久化

- 自动保存：数据变更后 **500ms** 防抖写入；视图变化后 **300ms** 防抖写入。
- 存三个键：文档、视图、主题；三者独立，任一损坏不得连带清空其余。
- 视图保存 `{x, y, scale}`，载入时缩放夹在 **25%–400%**；运行时缩放允许 **5%–400%**。
- 刷新后必须完全恢复：全部人物、关系、条目、类别、标签、手动偏移、折叠状态、主题、缩放与平移位置、选中对象（可恢复则恢复）。
- 写入失败（容量超限）必须提示并建议导出 JSON 备份，不得静默丢失。
- 载入旧版本数据时必须自动修复到当前不变量（未出生与出生日期冲突、悬空外键、重复 id），修复要幂等，不得每次刷新都改动数据。
- 提供「清空 / 新建」入口，清空前必须二次确认并提示先导出备份。

## 十三、给 AI 的实施建议

### 13.1 建议构建顺序

1. **骨架与坐标系统**：单文件、工具栏、画布（点阵、平移缩放）、右侧面板；先让空画布可拖动缩放。
2. **符号注册表**：先把 4 类符号表全部录入，再写一个「符号预览」页，确认每个符号画法与语义都正确；此时图例、含义说明、选择器都应已由表驱动。
3. **数据模型与规范化**：写空文档、载入修复、外键校验、日期解析、状态不变量。
4. **渲染单人**：符号、索引双框、已故叉、孕产标记、年龄、姓名、条目、折叠角标、选中框。先不连线。
5. **排版第一版**：分代、行距、代内顺序、伴侣相邻、单子女中点、多子女等间距、T 接头。
6. **连线与情感路由**：正交候选、代价函数、槽位、标记、光晕。
7. **交互**：点选/拖动/阈值、面板、右键菜单、新增入口、两条选择入口、取消语义、撤销。
8. **导出**：PNG → PDF → HTML；三者共用同一个 fit 与同一份 SVG。
9. **主题与持久化**：最后接入，避免早期反复改颜色。
10. **验收清单逐条跑**：每条都要能在界面上复现测试。

### 13.2 容易踩的坑

- **半截文件**：单文件很长，生成时容易截断 `<script>` 或丢 `</html>`。写完必须自查标签配对、脚本能执行、控制台无 `Unexpected end of input`。
- **符号表多处不一致**：渲染一处、图例一处、含义说明一处、选择器一处，四处改漏一处就会出现「图例有的符号画不出来」。必须一开始就表驱动。
- **求解器不收敛**：初始化就重叠、分离只推一边、目标函数来回拉扯、没有迭代上限，都会导致刷新漂移。必须设 24 轮上限与 0.02px 残差，并保证每个约束只作用一次（用锁避免重复纠偏）。
- **覆盖用户手动位置**：每次刷新把 `offset` 写回成绝对坐标，第二次刷新再叠加，位置会越跑越远。必须始终保存「相对基准的偏移」，并让被拖过的人受保护。
- **原生下拉不可控**：依赖原生 `select` 就做不到「展开即滚动到已选项并高亮」。选项多的枚举要自绘列表框。
- **触屏与鼠标双绑**：同时监听 `touchstart` 和 `pointerdown` 会一次点击触发两次，甚至误建两条关系。统一用 Pointer Events，触屏只额外处理双指。
- **命中测试没考虑缩放**：用屏幕坐标判断点中了谁，放大后会点偏。必须把指针坐标反算回世界坐标再命中。
- **NaN 污染**：除零、空数组取中点、未定义坐标参与运算，会让整张图消失。所有几何函数入口都要校验有限值。
- **撤销栈把 UI 操作也记进去**：选择、展开、缩放不该入栈；取消点选更不能入栈。否则用户按一次撤销只是「取消了一次没发生的事」。
- **导出受视口影响**：直接截当前画布会把缩放和平移一起导出。必须用内容包围盒与独立 SVG。
- **打印样式没隔离**：编辑器控件、面板、阴影、背景色进入 PDF，导致第 1 页花、第 2 页空。打印样式必须只保留图与明细。
- **本地存储超限**：把图片或二进制塞进 localStorage 会立刻超限。只存结构化纯文本，并在写入失败时提示导出 JSON 备份。
- **中继线断口**：浮点四舍五入会让竖线与横条差 1px，肉眼可见。统一取整到 2 位小数，并在渲染后断言接头。
- **跨代情感线压字**：只按直线画会把线压在姓名上。必须走正交候选与代价函数，并把文字区设为禁区。
- **把署名写进页脚**：模板里塞一句「© 作者 · MIT」最省事，但它会跟着每一张导出图、每一份 PDF 明细流出去。署名只写进源码顶部注释，页面与导出模板都不留位；「关于」框也别为了放版权而存在。
- **只写"零署名"、不写商用义务**：界面干净了，但源码注释里没写"商用必须署名"，等于把授权要求也一起删了。注释块里必须同时写明个人使用零署名与商用必须署名，并指向 `LICENSE` / `NOTICE`。
